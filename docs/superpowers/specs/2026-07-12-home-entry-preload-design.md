# 首页重型入口预加载设计

## 问题

闪退防护将新游戏向导、存档、世界书和智库管理器改为按需加载，同时首页过场改为完整播放后才切换页面。当前点击链路因此串行执行：先等待 1.6 至 1.8 秒动画，再下载和解析对应代码块。智库没有过场动画，但首次点击仍要等待代码块加载。

## 目标

- 保留现有首页动画时长和视觉表现。
- 动画入口在动画播放期间完成组件加载，动画结束后立即显示目标页面。
- 智库等无动画入口在首页空闲后完成低优先级预热，首次点击直接打开。
- 保留按需加载、代码块失败重试和启动阶段内存保护，不恢复重型组件静态导入。

## 方案

为 `lazyWithRetry` 增加可复用的 `preload()` 能力。成功进行中的预加载与 React 懒加载共享同一个 Promise，确保同一组件只发起一次导入；预加载失败不能产生未处理的 Promise 拒绝，并应清除失败缓存，让用户真正打开时重新导入并继续走现有错误处理和单次刷新保护。

首页三个带过场的入口在点击后的第一时间调用对应组件的 `preload()`，随后开始等待动画。组件加载和动画计时并行，但页面切换仍以完整动画结束为准：

1. 踏上旅途预加载 `NewGameWizard`。
2. 读取存档预加载 `SaveLoadModal`。
3. 如我所书预加载 `WorldbookManagerModal`。

首页首次稳定渲染后，通过 `requestIdleCallback` 低优先级预加载 `ZhikuManagerModal`；不支持该 API 时使用短延时回退。空闲任务在离开首页或组件卸载时取消，避免无效工作。首页按钮获得指针悬停、键盘焦点或触摸意图时也可提前触发对应预加载，作为空闲调度尚未执行时的补充。

不在首页一次性同步加载所有重型面板，也不预挂载弹窗内容。这样只缓存模块代码和解析结果，不创建大型 React 子树，不读取存档列表，不整理智库数据。

## 错误处理

- 背景预加载失败时静默清除失败缓存，不刷新页面。
- 用户实际打开组件时，由 `lazyWithRetry` 继续执行现有代码块错误识别和单次 cache-busting 刷新。
- 非代码块错误继续交给现有 ErrorBoundary，不改变错误语义。

## 验证

- 静态回归确认三个动画入口在等待动画前调用对应 `preload()`。
- 静态回归确认智库使用可取消的空闲预加载，并保留无 `requestIdleCallback` 的回退。
- 单元回归确认懒加载渲染和主动预加载共享同一个导入 Promise，不会重复加载。
- 保留闪退防护回归：重型首页组件不得恢复运行时静态导入。
- 运行 TypeScript 检查、闪退防护回归、内存回归和首页过场时序回归。

## 非目标

- 不缩短或删除首页动画。
- 不修改存档、世界书或智库内部的数据读取逻辑。
- 不预加载游戏内所有系统面板。
- 不处理与本次入口延迟无关的现有工作区改动。
